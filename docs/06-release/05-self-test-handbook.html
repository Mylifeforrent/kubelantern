01系统全景与设计原理

先建立一张正确的心智地图：请求从哪来、落到哪、哪个组件负责降噪、哪个组件负责 AI 治理。

1.1 部署全景：一台开发机上的 3 节点集群

KubeLantern 的本地演示环境刻意做成“平台自己也住在 K8s 里”：平台、PostgreSQL、Redis、演示业务、故障资源都在同一个 kind 集群中。这样巡检连接器才能用真实的只读 ServiceAccount 访问集群，而不是对着一个假数据源做演示。

1.2 一条告警的旅程：四步管道

告警从 webhook 进来后，不是“直接弹到页面上”，而是先落 PostgreSQL，再由 worker 异步推进四步：接入 → 去重 → 富化 → 关联。这就是为什么页面上能看到“管道四步卡”，也是为什么 seed 的 3 条演示告警会停在 received：seed 阶段用的是 no-op 入队，不会真的推进管道。

1.3 十项贯穿全局的设计原则

01先确定性，后 AI

巡检规则先产出结构化 finding；AI 只负责解释。没有模型时，告警、巡检、事件、通知仍然完整可用。

02窄权限 + 确定性外壳

集群连接器只加载 readonly 凭证；AI 工具默认只读；写操作需要审批与审计，而不是把 kubectl 权限直接交给模型。

03人在回路

关联规则在 candidate 模式下只能生成候选，必须人工确认才立项（BR-04）；AI 生成物同样需要确认（BR-05）。

04先落盘再入队

告警原文先写 PostgreSQL，再投 Redis 队列；队列丢失可由回放器补投，正确性不依赖队列可用性。

05模块化单体 + 同镜像多角色

API 与 5 类 worker 共用一个镜像，仅启动命令不同；单库内事务替代分布式 Saga，降低单人运维成本。

06队列分级隔离

告警管道与通知是高优先级队列；巡检和 AI 是低优先级长任务。巡检再慢，也不会占满告警管道的 worker。

07唯一 AI 出域口

所有模型调用都经 AI Gateway：先脱敏、再路由、查预算、过熔断、记调用日志。其他组件直连模型端点视为架构违规。

08只追加审计

审计日志、AI 调用日志、通知记录只追加，不提供 UPDATE/DELETE 路径；关键动作都能回溯到人、时间与对象。

09前后端边界清晰

前端权限只做菜单隐藏与按钮禁用；真正的 403/404 与团队行级过滤由后端权威执行。

10降级优先于报错

模型不可用走 NoAI；集群探活失败把巡检 run 标记 failed；通知渠道不可用按 IM → 短信 → 电话降级。主链路不被旁路故障拖死。

1.4 为什么是模块化单体，而不是微服务？

这是一个单人可运维的项目。微服务会把部署、监控、告警、排障、链路追踪的面各乘以服务数；而告警、事件、通知之间的跨域操作在单库内就是本地事务。所以项目选择模块化单体 + worker：Python 包按子域拆分（alerts / inspections / incidents / oncall / ai / clusters / notifications / iam），模块间只经内部 service 调用，禁止跨模块直查他域表。等到“多团队并行开发同一平台”或“单库容量触顶”再拆，触发条件写在架构文档里，防止提前微服务化。

队列任务优先级为什么要独立
q-alert-pipeline去重 → 富化 → 关联、回放、维护窗口收口高告警主链路不能被巡检/AI 长任务拖慢
q-notification通知投递、渠道降级高处置时效直接影响升级链
q-escalation升级超时检查中与通知解耦，按定时器推进
q-inspection巡检执行、调度 tick、集群探活低长任务，独立 worker 组
q-aiAI 任务执行、审批超时扫描低模型调用可能数十秒，不能影响告警

1.5 核心对象关系：从信号到闭环

告警 → 事件

Provider → Alert → IncidentCandidate（candidate 模式）→ Incident → Postmortem / StatusPageEntry。

告警也可以直接 convert-to-incident，或人工创建事件。事件与告警是多对多，关联关系落在 incident_alerts。

集群 → 巡检 → 告警

Cluster → InspectionPolicy → InspectionRun → Finding → 转告警（BR-09）→ Alert → 管道。

同一资源同一规则的 open/ack/in_progress finding 会被复用；已转告警的 finding 不再是 open，所以定时巡检会继续产生新 finding（见 §17 边界）。

值班 → 通知

OnCallSchedule → EscalationPolicy → NotificationRecord。每次投递、降级、Ack 都追加一条记录，而不是覆盖旧行。

AI 任务 → 审计

AITask → AICallLog；解释类任务还会写 AIExplanation。输入只存摘要，不存明文；脱敏映射本地加密保存。
